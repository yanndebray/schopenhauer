Here's the gist of the findings:

For the book use case: Schopenhauer scored 3/10. It was a thin CLI convenience — the hard problems (chapter assembly, font debugging, template styling) all happened outside it. Raw Pandoc with a defaults file would have worked just as well, and actually supports multi-file input and --toc that Schopenhauer doesn't expose.

Key gaps exposed: no multi-file input, no --toc/--number-sections, no pass-through for arbitrary Pandoc flags, no reference doc inspection, and the Jinja2 preprocessor chokes on {{table:source}} syntax in content (ironic — it just bit us rendering this very report).

Where the real value lives: the uncontested niche of AI-agent document generation. No competitor (Quarto, Typst, pypandoc, Sphinx) targets MCP + JSON Schema + data binding + Python API for agents. The architecture is right but the differentiating features (data binding, MCP, templates) are all still "planned."

Bottom line: Schopenhauer is a bet on the future. Today it saves you from memorizing Pandoc flags. Tomorrow — with data binding, MCP, and real templates — it could be the standard way AI agents produce professional documents.
